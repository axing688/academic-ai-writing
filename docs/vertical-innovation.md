# 垂直化创新设计：个人化学术写作引擎

> 核心理念：不做"更聪明的通用写作 AI"，做"最懂你领域、你实验室、你导师的写作系统"。
> 形式上的创新（界面、模板）会被迅速抄走；**数据与画像的积累是时间壁垒**。

---

## 一、定位重述

市面上的 AI 写作（Notion AI、各类论文降重工具、ChatGPT 通用对话）的共同缺陷：

| 通用 AI 写作的缺陷 | 对研究生的实际伤害 |
|---|---|
| 文献引用靠模型记忆 → **大量编造参考文献** | 引用造假是学术不端，不可用 |
| 文风是"互联网平均水平" | 导师一眼看出"AI 味"，与实验室文风脱节 |
| 不懂特定领域的术语规范与研究范式 | 术语翻译混乱、方法描述外行 |
| 每次对话从零开始 | 用户积累的反馈无法沉淀为产品资产 |

**我们的答案：把"大模型"替换为"你的文献 + 你的风格 + 你的领域"约束下的小模型行为（RAG + 画像注入）。**

---

## 二、七大核心创新点

### 1. 个人文献库 RAG —— 杜绝编造引用（★最高优先级）

- **上传**：PDF / CAJ / EndNote / BibTeX / Zotero 导入，自动抽取标题、作者、年份、摘要、正文
- **检索**：把论文正文切块建索引。AI 写作时先检索文献库，**只基于检索到的真实段落生成，并强制标注 [作者, 年份] 引用**
- **关键设计：引用可溯源**——生成的每个引用点击即可跳回 PDF 原文位置。模型"没检索到就不写"，从机制上消灭幻觉文献
- **自动综述生成**：按主题聚类文献，生成"文献综述矩阵"（作者 × 观点 × 方法 × 结论对比表），这是综述章节最痛的部分
- **引用格式**：GB/T 7714 / APA / IEEE 一键切换

### 2. 导师/实验室风格画像（★差异化最强）

分三层构建：

- **风格特征提取**：上传导师或已答辩师兄师姐的论文（3~5 篇即可），自动分析：
  - 句式统计（平均句长、被动句比例、长短句节奏）
  - 学术措辞库（常用连接词、程度副词、hedging 表达：如"本文认为/研究表明/值得注意的是"）
  - 段落结构范式（观点句→论据→引用→小结？）
  - 时态与人称习惯、图表描述句式
- **风格注入生成**：把画像编译成 system prompt 注入每次 AI 调用，输出"像这个课题组写的"
- **风格一致性评分**：写完后对照画像打分，标出"AI 味"最重的句子并给改写建议

### 3. 修改偏好学习 —— 数据飞轮（长期护城河）

- 记录每次「AI 生成 → 用户修改后插入」的 **diff**
- 从 diff 中归纳偏好："用户总是把'非常'改为'显著'""总是拆长句""总是删掉空洞的总结句"
- 偏好自动并入个人风格画像，**用得越久越像你**——这是竞品无法复制的数据资产

### 4. 导师批注回流

- 导师返回的批注版 Word（修订/批注）直接上传
- 自动抽取批注模式："导师三次批评文献综述缺乏批判性" → 转化为该章节的生成约束
- 下次生成同类内容时自动规避历史批评点

### 5. 领域知识适配层

- **术语库**：领域术语 + 固定译名（如"transformer 一律不译"），生成时强制一致
- **研究范式模板**：工科（方法-实验-指标）、人文（论点-文本细读）、医科（伦理-病例-统计）范式各不相同，按学科选择综述/方法章节的论述骨架
- **学科自查清单**：不同学科的开题/答辩规范（如医科必须有伦理声明）作为生成时的检查项

### 6. 阶段化写作流水线

研究生写作是流程，不是单点。按阶段组织功能而非按"功能按钮"：

```
选题 → 开题报告 → 文献综述 → 研究设计 → 实验/调研 → 结果与讨论 → 结论 → 答辩 PPT
```

每个阶段：专属提示策略 + 该阶段文献库的子集 + 阶段验收清单（开题是否包含研究问题/意义/方法/进度四要素）。答辩阶段还能基于全文生成**预答辩问答**（AI 扮演评审提问）。

### 7. 学术合规守护（垂直场景的信任壁垒）

- **AI 使用声明生成**：按学校/期刊要求生成规范的 AI 辅助声明
- **自我查重风险提示**：改写降重时显示与文献库原文的相似度，而不是盲目"降重"
- **未发表数据隐私**：在研数据是研究生的命根子——支持**本地索引模式**（BM25/本地向量，文献内容不出本机），这是对通用云端产品的直接差异化

## 三、技术架构增量（在现有栈上）

```
前端 (React)                      后端 (Go)                    存储
├─ 文献库管理页      ──上传──▶  ├─ PDF 解析 (pdfcpu/      ──▶ MySQL（文献元数据）
├─ 引用溯源侧栏                  │   go-pdfium + 抽取文本）     文件系统（原始 PDF）
├─ 风格画像页        ──构建──▶  ├─ 分块 + 索引服务          ──▶ 向量索引:
│   (特征分析/评分)              │   ├─ 方案A: API embedding     SQLite-vec / Qdrant
├─ 写作流水线视图                │   └─ 方案B: BM25 纯本地       本地: IndexedDB
└─ 偏好学习(自动)   ──diff──▶    ├─ RAG 检索服务              偏好/画像: MySQL
                                └─ 风格画像编译服务
```

关键取舍：
- **检索先行本地化**：BM25 全文检索零成本、零外部依赖，先落地；embedding 检索作为增强（可选配置用户的 API Key）
- **风格画像可解释**：画像不是黑盒 embedding，而是人类可读、可编辑的"风格规则卡"，用户可以手动微调
- 现有 12 家服务商适配层不变，RAG 与画像作为**生成前置层**插入 ai.ts 的调用链

## 四、与竞品的差异总结

| 维度 | 通用 AI 写作 | 本方案 |
|---|---|---|
| 引用 | 模型记忆（常编造） | 只引用文献库内真实文献，可溯源 |
| 文风 | 通用腔 | 导师/个人画像注入 + 持续学习 |
| 领域 | 通用 | 学科范式 + 术语库 |
| 数据 | 全部上云 | 支持纯本地模式，未发表数据不出机 |
| 沉淀 | 无 | 文献库、画像、偏好构成迁移成本 |

## 五、实施路线图

**Phase 1（可立即开工，纯前端可演示）**
1. 文献库页面：PDF 上传 + 文本抽取（pdf.js）+ 分块 + BM25 本地索引（IndexedDB）
2. RAG 写作模式：写作时检索文献库，生成带 [作者, 年份] 的真实引用
3. 引用管理：文献条目列表 + GB/T 7714 格式化导出

**Phase 2（前后端联动）**
4. 风格画像页：粘贴/上传导师论文 → 特征分析 → 风格规则卡 → 注入生成
5. 风格一致性评分器
6. 后端文献库持久化（多设备同步打通）

**Phase 3（数据飞轮）**
7. diff 偏好学习引擎
8. 导师批注回流（Word 批注解析）
9. 阶段化写作流水线 + 预答辩问答
